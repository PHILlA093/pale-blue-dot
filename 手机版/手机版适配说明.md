## 二、架构问题:AI 调用不再依赖桌面宿主

### 三模式调用层(`js/ainet.js`)

唯一入口 `window.QGAi.request({key, json, model, messages, max_tokens, temperature})`,**永不 reject**,一律 resolve 成 `{ok:true,content}` 或 `{ok:false,err:'可读中文'}`;调用方(破卷 `train.js` / 观澜 `demo.js`)只判 `r.ok`,完全不关心自己在哪种环境里。

| 模式 | 检测方式 | 请求路径 |
|---|---|---|
| **A · 桌面宿主** | `typeof window.chrome !== 'undefined' && window.chrome.webview && typeof window.chrome.webview.postMessage === 'function'` | 复用各页**原有**的 `hostReq`(页面通过 `QGAi.setHostSender(hostReq)` 注入),桌面行为零变化 |
| **B · Capacitor 原生壳** | `window.Capacitor && typeof window.Capacitor.isNativePlatform === 'function' && window.Capacitor.isNativePlatform()`(旧版无此方法时退化为 `platform !== 'web'`) | **直连** `https://api.deepseek.com/chat/completions`,带 `Authorization: Bearer <key>`。**不绕 `/api/ds`** |
| **C · 普通浏览器** | 以上都不是 | `POST /api/ds`,由 `server.js` 反向代理转发 |

**CapacitorHttp 形态兼容**:`pickJson(res)` 先判 `typeof res.json === 'function'` 走标准 `Response`,否则当已解析对象用(`res.data` 或 `res` 本身);`pickStatus(res)` 依次尝试 `res.status` / `res.statusCode` / `res.ok`。这样 APK 里不会出现 `res.json is not a function`。

**错误可读性**:401(Key 无效)/ 402(余额不足)/ 429(太频繁)/ 404(`/api/ds` 未就绪,提示用 bat 启动)/ 502(电脑连不上外网)/ 超时(60s,带秒数)——全部是中文可读提示,没有静默失败。

### 本地服务器 `server.js`

- 静态伺服:URL → 文件,归一化后必须仍在站点根目录内(防目录穿越),`/` → `index.html`,`Cache-Control: no-cache`。
- `POST /api/ds`:无 `Authorization` → **401 JSON**;否则把请求体**原样**转发到 `https://api.deepseek.com/chat/completions`,上游状态码与响应体(含 SSE)原样 pipe 回前端;上游不可达 → 502 + 可读原因;请求体上限 8MB。
- 上游超时 180s(与桌面宿主的兜底一致);客户端断开时同步掐掉上游连接。
- **不落盘、不写逐请求日志、不打印 Key 与请求体**。
- 另有 `GET /api/health`(自测用)与非 POST 的 `/api/ds` → 405。

### 启动脚本 `启动手机版.bat`

检查 Node → `ipconfig | findstr /r /c:"IPv4"` 取第一条局域网 IPv4(去空格)→ 打印醒目提示
`http://<本机IP>:8080/`(以及「手机与电脑连同一个 Wi-Fi」「防火墙需允许专用网络」)→
`start "" http://127.0.0.1:8080/` 打开本机浏览器 → 前台 `node server.js 8080`(Ctrl+C 停止)。
**内容 100% ASCII**(中文提示会让 cmd 的 OEM 代码页解析错乱)。

## 六、移动端适配要点(实现位置)

### 视口与触屏基础(三页)
`<meta name="viewport" content="width=device-width,initial-scale=1,viewport-fit=cover,user-scalable=no">`;`100dvh`(带 `100vh` 兜底,`@supports` 包裹);`--safe-t/-b/-l/-r` 变量统一取 `env(safe-area-inset-*)`(不支持 `env()` 时自动为 `0px`);`html,body { overscroll-behavior: none; }`;`#scene { touch-action: none; }`。

### 窄屏布局(全部关在 `@media (max-width: 768px)` 内,宽屏不受影响)
- **顶栏**:两行(`--topbar-h: calc(106px + var(--safe-t))`),隐藏 `.brand` 与 `.winctrl`(─ ▢ ✕),保留 ☰ / 科目切换 / 搜索 / ⟳ / ⌖;所有可点元素 ≥44×44px;输入控件字号 ≥16px(防 iOS 聚焦自动放大);`#statBar` 压到 10.5px / 94px 宽。
- **左侧栏**:全屏抽屉(100% 宽 × 100% 高,z-index 70 盖过顶栏),内部字号整体上调、列表项 ≥44px;关闭方式 = 点顶部遮罩条 / 向右滑动 / 再点 ☰;打开时隐藏「破卷」按钮。
- **详情面板**:底部抽屉,`--sheet-h` 三档 55/62/70dvh,圆角 18px,`env(safe-area-inset-bottom)` 内边距,头部有拖拽横条,内部 `.detail-scroll` 可滚动(`overscroll-behavior: contain`)。
- **「破卷」浮动按钮**:`bottom: calc(14px + var(--safe-b))`;`html.sheet-open` 时上移到 `calc(var(--sheet-h) + 10px + var(--safe-b))`,**不压底部抽屉内容**。
- **观澜**:主窗面板窄屏整屏(画布上 46% / 对话下),独立页同样整屏;工具条折行、按钮 36px 高;隐藏「独立窗口」与窗口控件。

### 3D 知识云的触屏操作
- 单指拖拽旋转、双指捏合缩放:交给 `vendor/OrbitControls.js`(`touches.ONE = ROTATE`、`TWO = DOLLY_PAN`),`#scene` 的 `touch-action: none` 保证手势不被浏览器抢走。
- 轻触选中:触屏容差 **12px**(鼠标仍 6px),超过即判定为旋转拖拽,不选中。
- 双击聚焦:触屏浏览器不派发 `dblclick`,所以自研识别 —— 两次轻触间隔 **< 320ms** 且落点相距 **< 32px** 即视为双击;桌面 `dblclick` 保留并用时间戳去重(避免重复触发)。

### train / guanlan 宽度自适应
- `train.html`:整套窄屏样式在页面内联 `<style>` 里(顶栏/钥匙行/状态行/题目卡/选项/按钮全部单列 + ≥44px)。

## 八、没做到 / 打折扣的部分(如实说)

1. **模式 B 无法真机验证**。本机没有 Android 设备/模拟器,也没有 APK;上面的验证是**注入桩**,证明的是「检测正确 + 走的是直连 URL + 兼容 CapacitorHttp 的两种响应形态」,**没有证明** CapacitorHttp 在真机上确实绕过了 CORS。这一环需要打包那一路在真机/模拟器上确认。
2. **所有数据来自无头 Edge 153 + 设备模拟**,不是真实手机。**iOS Safari 完全没测**(`env(safe-area-inset-*)`、`100dvh`、`user-scalable=no` 在 iOS 上的行为未验证);安卓 WebView 的旧版本(缺 `:has()` / `dvh` / `env()`)只能保证「降级不崩」,没有实测。
3. **左侧抽屉的「遮罩」是妥协方案**。抽屉按要求做成 100% 宽 × 100% 高(全屏),此时屏幕上不存在「抽屉外面」,所以遮罩只覆盖**顶栏高度那一条**(文案「✕ 点这里关闭侧栏」)。点它关闭、向右滑动关闭都可用,但它不是覆盖全屏的那种遮罩。
4. **底部抽屉的拖拽不是连续自由高度**:拖动时跟手位移,松手吸附到 55% / 62% / 70% 三档,下拉超过 `max(90px, 抽屉高×25%)` 才关闭。
5. **观澜 canvas 在手机上不能缩放/平移**,双击复位也不生效(canvas 引擎只处理单指拖动图元与鼠标滚轮,`dblclick` 在触屏上不派发)。这是引擎既有能力边界,本次没有扩展引擎(不在「只改像素尺寸与 CSS 尺寸」的范围内)。
6. **Service Worker 在局域网地址下不生效**:`http://192.168.x.x:8080` 是非安全上下文,浏览器拒绝注册 SW,手机浏览器访问时**没有离线缓存**。APK(`https://localhost`)与 `localhost` 自测正常。已如实写进 README。
7. **破卷在手机上拿不到真实高考真题素材**(本地真题档案 / 必应联网检索 / 本机知识点档案三条路都依赖桌面宿主)。程序要求「必须含 N 道真实真题」,所以难度二~五会反复重试到上限,慢且费 token。**建议手机上用「难度一 · 真题 0%」**。这是宿主依赖,不是可以在纯网页层绕过的东西;我只把限制写清楚了,没有改判定逻辑。
8. **没有做桌面回归测试**。桌面版目录一字未改,手机版这套代码里的窄屏规则全部在 `@media (max-width:768px)` 内、`labelEager()` 在宽屏恒真、`mobile.js` 在宽屏空转 —— 逐条核对过,但**没有实际在桌面窗口里跑过**,回灌桌面版前建议再验一遍。
9. **`#statBar` 在超窄屏(≤380px)下仍可能被省略号截断**,只是不会撑出横向滚动。
10. **未做真机性能剖析**:没有 GPU 帧率、内存、耗电数据;「首屏 677ms」是无头 SwiftShader 下的数字,真机 GPU 可能更好也可能更差。
