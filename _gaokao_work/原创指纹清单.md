## 3. 举证用法(可直接执行的命令)

### 3.1 场景一:对方抄了 APK

APK 就是 ZIP,先解包再搜前缀:

```powershell

New-Item -ItemType Directory -Force .\unz | Out-Null
tar -xf .\可疑应用.apk -C .\unz
Get-ChildItem .\unz -Recurse -File |
  Select-String -Pattern 'QG-20260920-' -Encoding UTF8 |
  Select-Object Path,LineNumber,Line
```

```powershell
# 方式 B:PowerShell 原生解压(需先把 .apk 复制成 .zip)
Copy-Item .\可疑应用.apk .\unz\suspect.zip
Expand-Archive .\unz\suspect.zip -DestinationPath .\unz\x -Force
Select-String -Path .\unz\x\assets\public\js\*.js,.\unz\x\assets\public\*.html `
  -Pattern 'QG-20260920-' -Encoding UTF8
```

```powershell
# 方式 C:不解包,直接在 APK 字节里搜(最省事,能命中被压缩的条目之外的一切)
node -e "const fs=require('fs');const b=fs.readFileSync(process.argv[1]);const s=b.toString('utf8');const i=s.indexOf('QG-20260920-');console.log(i<0?'MISS':'HIT @'+i+' :: '+s.slice(i-60,i+60));" .\可疑应用.apk
```

### 3.5 怎么把「命中」升级成「实质性相似」

1. **先固定证据**:对可疑 APK / exe / 网站做完整性哈希(SHA-256)并录屏、公证或第三方时间戳。
2. **再证明同源**:用 3.1–3.3 的命令导出命中清单(文件路径 + 行号 + 原文片段),
   与本清单第 2 节逐条对照。**命中 Build ID 属于「完全相同」级别的一致性**——
   这是一串不可能独立重现的随机十六进制,结合日期段,足以排除巧合。
3. **再看结构相似**:把命中的 15/16 个文件清单与下表比对——这些文件是
   `app.js / demo.js / train.js / glcanvas.js / mainbridge.js / data*.js / 三个 html / style.css`,
   **文件集合本身**就构成「表达层」的复制证据(不是玩法,是具体文件)。
4. **看对方删了什么**:如果可见署名(D17/M17)被删除、但隐藏指纹仍在,
   说明其**明知**作品来源而刻意去除署名 —— 这会显著加重其主观恶意。
5. **反证**:对方若主张「独立开发」,则需解释为何独立写出的代码里会出现
   一个只属于本工程的、由本工程声明的哈希串。
