# 穷观 · 化学实验台（观澜化学模式）设计契约

> 给**实现它的 agent** 看的接口契约。目的：把高中化学的**典型反应**做进「化学观澜」，
> 让学生能"做"一遍：选试剂 → 调条件 → **看现象** → 写方程式 → 得结论。
> 与物理实验台（`docs/物理实验台设计.md`）**同架构、同观感、同工程约束**，差别只在"测量"换成"现象"。

---

## 1. 边界与红线

1. **只有化学科目出现**：判据照抄物理那套（`isPhysicsSubject()` 的化学版：`window.CUR_SUBJECT === 'chem'` → `localStorage('qg_subject')` → 主窗心跳 `localStorage('qg_live_state').subject`）。**非化学科目下不得出现任何 `cl-` 前缀 DOM、不得注入 `#clCSS`**（数学/物理/英语/生物一律不受影响）。
2. **纯 ES5、零依赖、不用网络、不用 `eval`/`new Function`**；每个新文件头部带指纹 `QG-20260920-5e5d5a` 与版权行。
3. **不许编造化学**：每个反应的**现象、方程式、条件、原理**都必须去权威来源核对（人教版教材/课标/真题解析），并在回报里列出**来源 URL 与"全文还是摘录"**。
   ⚠ 本机 `web_fetch` **读不了 PDF**（返回 `unsupported content type`），要 PDF 就用 `Invoke-WebRequest`（代理 `http://127.0.0.1:7897`）下载后用 `%TEMP%\qg_gk2025\tools\` 里的抽取工具；只拿到摘录就写明"这是摘录"。
4. **不改** 任何既有文件（`js/pslab.js`、`js/psandbox.js`、`js/demo.js`、`guanlan.html`、`css/style.css`、`data*.js`、`js/pslab/*`）—— 本轮**只新建** `js/clab.js` 与 `js/clab/*.js`，接线由主线在物理版发布之后统一做。

```
js/clab.js            核心(注册表 + 三栏 UI + 现象表 + 方程式校验与展示 + 结论卡 + 测试接口)

```

核心暴露 `window.QG_CLAB`：`register(id, spec)` / `list()` / `open(id)` / `close()` / `current()` /
`setParam(k,v)` / `react(n)`（做 n 次反应/观察，返回新增的现象行） / `clear()` / `table()` / `graph()` /
`conclude()` / `run(seconds)` / `state()` / `isMounted()` / `mount(el,opts)` / `unmount()` / `audit()` / `balance(eq)`。

**`register(id, spec)` 的字段**：
```js
window.QG_CLAB.register('na-water', {
  id: 'na-water', name: '钠与水的反应', group: '金属与非金属单质',
  aim: '观察钠与水的反应现象并写出方程式',
  principle: '2Na + 2H₂O = 2NaOH + H₂↑（钠的密度小于水、熔点低、反应放热）',
  apparatus: ['小烧杯', '镊子', '滤纸', '钠块', '酚酞溶液'],
  steps: ['向烧杯中加入约 1/2 体积的水，滴入 2 滴酚酞', '用镊子取一小块钠，滤纸吸干煤油', '投入水中，观察现象', '反应后滴加酚酞检验产物'],
  params: [                                  // 可调条件：浓度/温度/用量/催化剂…
    { key: 'naMass', label: '钠块质量', unit: 'g', min: 0.05, max: 0.5, step: 0.01, value: 0.2 },
    { key: 'temp',   label: '水温',     unit: '℃', min: 5,  max: 80, step: 5,  value: 25 }
  ],
  // 关键方法：做一次反应/观察。返回值必须包含下面这些键（缺一即不合格）
  react: function (p, ctx) {
    return {
      phenomena: ['钠浮在水面上', '熔成闪亮的小球', '四处游动并发出嘶嘶声', '溶液变红'],
      equation: '2Na + 2H2O = 2NaOH + H2↑',   // 必须配平（核心会校验）
      ionic: '2Na + 2H2O = 2Na+ + 2OH- + H2↑', // 离子方程式；不适用时给 ''
      type: '置换反应（金属与水）',
      conditions: '常温',                        // 加热/催化剂/光照/浓硫酸…
      measures: { dH: -184.0 }                   // 可量化量（没有就给 {}），单位在 columns 里声明
    };
  },
  columns: [ { key: 'dH', label: '反应热', unit: 'kJ/mol' } ],   // 可为空数组（纯定性）
  graph: null,                                 // 纯定性反应必须写 null；有定量数据才给 {x,y,fit,title}
  conclude: function (rows, p, ctx) {
    return { text: '钠与水剧烈反应生成 NaOH 和 H₂…', equation: '…', ionic: '…',
             errors: ['钠块表面煤油未吸干', '钠块过大导致燃烧', '水温过高使现象观察不全'] };
  },
  draw: function (g, p, state) { /* 画烧杯/试管/现象（颜色、气泡、沉淀、火焰） */ },
  step: function (p, state, dt) { /* 可选：推进动画 */ },
  onPointer: function (ev, p, state) { /* 可选 */ }
});
```

**核心必须提供**：
- **方程式配平校验** `balance(eq)`：解析 `化学式 + 系数`，逐元素（与电荷）核对守恒 —— 不配平就**在界面上标红并说明哪个元素不守恒**（这是化学里唯一客观的对错判据，务必实现）。
- **现象表**（列 = 第几次 / 现象 / 方程式 / 条件）、**结论卡**（结论 + 方程式 + 离子方程式 + ≥2 条误差/注意）、
  **条件区**（参数滑块 / `type:'select'` 下拉框）、**中栏实验台 canvas**（米白纸色 `#F4F1EA` + 墨色 `#26221C` + Georgia 斜体，与物理实验台同一观感）、
  工具条：`▶ 开始/⏸ 暂停`、`🔬 观察一次`、`↺ 重置`、`清空`。
- 纯定性反应：`columns: []`、`graph: null` 合法；**但只要给了定量列就必须能作图**（与物理同一套拟合规则）。

## 4. 每个反应的验收（探针会逐条查）

1. `list()` 里出现该 id，`open(id)` 后 `state().open === true`；
2. `react()` 返回的 `phenomena` **非空且 ≥2 条**、`equation` **配平通过**（`balance()` 返回 ok）、`conditions` 非空、`type` 非空；
3. **条件真的影响结果**：至少 2 个参数改动后，现象或量化量按化学规律变化（例：Na 块变大 → 现象更剧烈/放热更多；温度升高 → 出现浑浊更快；加催化剂 → 放出气体更快）；
4. `conclude()` 返回 `{text, equation, ionic, errors[]}`，`errors.length ≥ 2`；
5. **化学事实正确**：现象与权威来源一致（颜色/沉淀/气味/条件）——探针只做"非空 + 与 spec 自述一致"的机械校验，**事实正确性由各组自己对来源负责**；
6. `draw()` 不抛异常且画布像素签名会变（`run(1)` 或 `react()` 后）；
7. 纯定性反应：`graph()` 返回 null 且**这是合法的**；给定量列的反应必须 `points.length ≥ 5`、线性关系的 r²>0.9 ——
   **但 r² 的判据见下面「§4b 探针判据补充」，别按字面扫满量程**；
8. 全程 0 console 异常、0 register 警告。

## 4b. 探针判据补充（2026-09-29 独立验收后追认 —— 写探针前必读）

**① `balance()` 的四档，只有 `unbalanced` 是缺陷**：`ok` / **`no-equation`（焰色、碘的萃取、SO₂ 品红加合物 —— 物理变化或无固定组成，组里老实写"无化学方程式"，这是合法写法，不许判红）** / `unbalanced`（真不配平，界面标红并指出元素/电荷）/ `unparsed`（解析失败，黄字）。
另：`NH3·H2O`（人教版标准写法）与「全角分号连写的两段方程式」在旧 parser 下会被判 `unparsed` —— 核心已补 `·` 与 `;`/`；` 支持。

**② r² 只在三个条件同时满足时才有意义**：x 有分布（不能是常数）＋ y 非常数 ＋ **落在该反应自述的线性区内**。
- **扫满量程会假红**：`flame-test` 扫到 2.0 得 0.8696、`gas-collection` 扫到 60 s 得 0.8324、`so2-properties` 扫到 0.50 得 0.8138 ——
  而它们**在自述线性区内**分别是 **1.0000 / 0.9384 / 0.9428**（note 里都写明了"过了某点就饱和，应缩小范围重测"）。
- **y 为常数时核心会返回 `r²=1`（退化假绿）**：`iron-ion-test` 用默认 Fe²⁺ 试样时颜色恒 0，就命中了这一条 → 判据要加"y 非常数"。
- **不要把自变量与累加量同时变**：`kmno4-titration` 的 x 是"每次观察累加的滴定体积"，与自变量一起变会得到无意义的 r²（实测 0.8511）；
  改成"固定条件重复观察"后 **r²=1.0000**。

**③ 方向性扫描前必须把其余参数复位**（`open(id)` 建新会话）：否则前一个 select 停在上次的选项上会**假红**（验收第一版就因此误判了 `methane-substitute` / `starch-hydrolysis`）。

**④ 参数组合扫描是必须的，而且每组都要读状态**：`open()` 会重置 `lastError`/`drawErrorCount` —— 所以"每个反应只读一次"会漏掉
**只在某个参数组合下才炸**的缺陷。验收实际做法：每个反应 ≥60 组（每个 numeric 的 min/mid/max × 每个 select 的全部选项），
**每组都读** `state().lastError`、`drawErrorCount(id)` 与反应错误计数。**这条抓到了一个必然可达的崩溃**（见 ⑤），而所有"默认条件下"的检查都是绿的。

**⑤ 必然可达的边界要看数字本身**：`precipitate-convert` 曾在 `nX === nAgCl`（严格相等）处算出 `cAgEq = null`，
而守卫写成 `if (!isFinite(x))` —— **`isFinite(null) === true`**（null 当 0）→ 守卫失效 → `x.toExponential()` 抛 TypeError →
现象表不出行、画布红字"绘图出错"、`QG_CLAB.react()` 把异常抛给调用方。
**为什么"必然"**：`0.2×0.1` 与 `0.1×0.2` 是同一个 IEEE754 值，而 `cAgNO3` 滑块上界正好 0.20、`dropsAg` 默认 2 → 严格相等一定命中。
**教训**：① 判 null 要写 `x === null || x === undefined || typeof x !== 'number' || !isFinite(x)`，**别用 `!isFinite(x)` 单独当守卫**；
② 任何格式化函数都要能接住"表示无有效值的 null"；③ 滑块量程端点要当作**必然会被点到的**边界来设计。

**⑥ 判据必须带负对照**：注入一次中途抛错 / 把修好的形状改回去，**判据要变红**才证明它不是瞎的（物理那边就是这么定规矩的，见 `AGENTS.md` §13）。
