**⚠⚠ 第三次同类的坑（2026-09-30 补记，务必读完）——「API 全绿 ≠ 能玩」**：
沙盒的"事件与相互作用"上线后，用户实测**一个事件都触发不了**。我用真指针事件复现（headless CDP `Input.dispatchMouseEvent` 真按下/移动/松开）：
```
真拖 U、I、R 到台面 → bodies 最终只有一颗 kind:'I' 的电流实体，eq 始终 null，eqEvents 空
对照 API addBody(['U','I','R']) → {eq:'ohm', readout:{I:3,U:6,P:18}}   ← 一次成功
```
根因两条：① **26 条公式规则只挂在 `addBody()`（API 路径）与"并入已有实体"上，没接进"游离字母 → 游离字母"的真交互合并路径**；
② **`I`/`q` 仍然"落字即生成场实体"**（上轮的"加法式"只覆盖了 `B`/`E`），而带 `kind` 的实体既不并入也不接受并入。
**教训（与本模块 §13 开头那条 `window.open` 是同一族，这是第三次）**：
- **凡是"能拼出来/能点开/能触发"的断言，必须用真指针事件/真点击驱动**（`Input.dispatchMouseEvent` 或 `.click()`），
  **不许只写 `addBody([...])` / 只走 API** —— API 路径绿得再整齐，也不代表玩家能做到。
- 探针里要**同时**保留两条：API 路径（快、定位准）+ **真交互路径**（慢、但才是用户看到的）。
- 顺带记住两个实测细节：① 沙盒会**把手速转成初速度**，字形落点后会滑走，所以"合并"必须在**松手那一刻**判定，别依赖"停在哪里"；
  ② `.ps-table` **把右侧字形托盘包在里面**，用 `.ps-char` 取位置时必须排除 `.ps-panel` 里的（`e.closest('.ps-panel')`），
  否则你量到的是托盘坐标、拖到的是托盘（我为此白跑了三轮）。
- **"界面上没有设参数的手段"也要当缺陷报**：短路要 `R→0`、碰撞要恢复系数 `e`、斜面要 `μ` —— 若 UI 够不到这些状态，
  功能就等于不存在（沙盒里没有任何 `input`/`slider`，只有字形本身当"开关"，例如"放下 μ 字形 = 有摩擦"）。
